# Data — Yardi Matrix feeds, Atlanta MSA (April 2026 snapshot)

These are the raw input files for the rent AVM. All are restricted to the Atlanta-Sandy Springs-Alpharetta MSA (CBSA 12060). See the project brief one level up for what each feed contains and how they relate.

| File | Rows × cols | Granularity | Role |
|---|---|---|---|
| `042026-property-enriched-12060.parquet` | ~2,121 × 59 | One row per property | Building-level reference (lat/lon, amenities, year_built, quality grades) |
| `042026-unit-mix-enriched-12060.parquet` | ~6,887 × 12 | One row per (property × unit_type) | Floor-plan breakdown (sqft, beds, baths, unit counts) |
| `042026-rent-12060.parquet` | ~6,891 × 7 | One row per (property × unit_type) | **TARGET** — asking rent at 2026-03-01 |
| `042026-hist-rent-12060-12060.parquet` | ~708,825 × 7 | One row per (property × unit_type × month) | 24-month historical rent panel (~11 years going back) |
| `yardi_sales_atl.parquet` | ~600 × ? | One row per property sale | Comparable-sales reference (optional) |
| `atlanta_landmarks.json` | 11 landmarks | One per landmark | Curated coordinates: Buckhead, Midtown, Downtown, ATL airport, Ponce City Market, Battery Atlanta, GA Tech, ... |
| `atlanta_landmarks.csv` | 11 landmarks | Same as JSON | Identical content, easier to skim in Excel |

## Joining the feeds

```
                  property-enriched
                        │
              property_id│  source_property_id
                        ▼
                  unit-mix-enriched ────────┐
                        │                   │
        property_id +   │  unit_type        │
                        ▼                   ▼
                       rent (TARGET)    hist-rent (panel)
                        │                   │
                        └───────────────────┘
                            join on
                       (property_id, unit_type)
```

The model's prediction target is one row from `rent`. Every other feed feeds features into it.

## Update cadence

These are the **April 2026 monthly snapshot.** Yardi drops a new snapshot the first week of every month. When you eventually re-run the pipeline against a fresh snapshot, you'll point the file paths at the new month's files (e.g., `052026-rent-12060.parquet`).

## What's NOT in this folder

- The pretraining table `pretraining_v2.parquet` (built by joining property-enriched and unit-mix-enriched). This is generated by `prime-mfr-pretrain` — don't worry about it for Phase 1; you're working with raw feeds.
- Any model outputs, OOF predictions, or metrics. Those live in `artifacts/` at the repo root and you should not look at them in week 1 (see the "What you should not do" section of the project brief).

## Sample size context

These are small data by ML standards (~7k training rows, 700k historical rent observations). That means:

- **You can iterate fast.** Loading every parquet into pandas costs a few seconds. No need for Spark.
- **Cross-validation matters a lot.** With 7k rows, a single 80/20 split would swing by 5-15% depending on the random seed. The production pipeline uses 5-fold GroupKFold for this reason.
- **A single weird outlier moves metrics.** A $20,000/month penthouse can drag MAPE around. Inspect tails before reporting numbers.
